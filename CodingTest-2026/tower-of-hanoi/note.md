# Problem: Tower of Hanoi

문제 요약: 20개의 원반으로 하노이의 탑을 최소 횟수로 수행할 때, K번째 이동 직후 각 막대에 남아 있는 원반 크기의 합을 구한다.

## 풀이

### 문제 정보
- 난이도: Lv 02 정도 
- 주제: 하노이의 탑, 수학, 비트 연산, 시뮬레이션
- 문제 핵심 
  - 원반별 이동 주기 규칙 활용
  - 홀짝 방향에 따른 위치 계산
- 최초 풀이: 260811 
- 수정 버전: 260923

### 접근법
1. Solution1: 원반별 이동 횟수 직접 계산하 방식 (권장)
   - 각 원반의 이동 주기를 이용해 K번의 이동을 직접 시뮬레이션하지 않고, 각 원반의 현재 위치를 O(1)에 계산한다.
2. Solution2: 이동 번호 기반 시뮬레이션 방식
   - 각 이동 번호의 최하위 1비트를 이용해 움직이는 원반을 찾고 K번째 이동까지 상태를 갱신한다.


## Solution1: 원반별 이동 횟수 직접 계산하는 방식 (권장)
### 코드 설계
1. K를 입력받는다.
2. 세 막대의 원반 크기 합을 저장할 `rodSum[3]`을 만든다.
3. 원반의 크기를 `1 ~ 20`까지 순회한다.
4. 현재 원반이 K번째 이동까지 움직인 횟수를 계산한다.
5. 원반 번호의 홀짝에 따라 이동 방향을 결정한다.
6. 이동 횟수와 방향으로 현재 막대의 위치를 계산한다.
7. 해당 막대의 합에 현재 원반 크기를 더한다.
8. 세 막대의 합을 순서대로 출력한다.

### Java
- 구현 파일: `Solution1.java`
- 핵심 문법:
  - 예: `BufferedReader`
  - 예: `StringTokenizer`
  - 예: `Math.min()`, `Math.max()`

### Python
- 구현 파일: `Solution1.py`
- 핵심 문법:
  - `int(input())`: K를 정수로 입력받는다.
  - `1 << n`: 비트 시프트를 이용해 `2^n`을 계산한다.
  - `//`: 정수 나눗셈으로 원반의 이동 횟수를 계산한다.
  - `%`: 세 막대를 순환하는 현재 위치를 계산한다.
  - `print(*rod_sum)`: 리스트의 값을 공백으로 구분하여 출력한다.

### 복잡도
- 시간복잡도: O(20) = O(1)
- 공간복잡도: O(1)


## Solution2: 이동 번호 기반 시뮬레이션 방식
### 코드 설계
1. 초기에는 모든 원반이 첫 번째 막대에 있으므로 합을 `[210, 0, 0]`으로 설정한다.
2. 각 원반의 현재 막대를 저장하는 `position` 배열을 만든다.
3. 이동 번호를 `1 ~ K`까지 순회한다.
4. 현재 이동 번호의 최하위 1비트를 이용해 움직이는 원반을 찾는다.
5. 원반 번호의 홀짝에 따라 이동 방향을 결정한다.
6. 현재 막대의 합에서 원반 크기를 뺀다.
7. 다음 막대의 합에 원반 크기를 더한다.
8. 원반의 현재 위치를 갱신한다.
9. K번 이동 후 세 막대의 합을 출력한다.

### Java
- 구현 파일: `Solution2.java`
- 핵심 문법:
  - `BufferedReader`: K를 빠르게 입력받는다.
  - `Long.numberOfTrailingZeros()`: 이동 번호의 뒤쪽 연속된 0의 개수를 구한다.
  - `int[] position`: 각 원반의 현재 막대 위치를 저장한다.
  - `int[] rodSum`: 각 막대의 원반 크기 합을 저장한다.
  - `%`: 세 막대를 원형으로 이동한다.

### Python
- 구현 파일: `Solution2.py`
- 핵심 문법:
  - `range()`: 1번째부터 K번째 이동까지 반복한다.
  - `move & -move`: 가장 낮은 위치의 `1` 비트만 추출한다.
  - `bit_length()`: 움직이는 원반 번호를 계산한다.
  - 리스트: 각 원반의 위치와 각 막대의 합을 저장한다.
  - `%`: 세 막대를 원형으로 이동한다.

- 시간복잡도: O(K)
  - `K < 2^20`이므로 최대 약 100만 번 반복한다.
- 공간복잡도: O(1)
